# CLAUDE.md

Read [AGENTS.md](AGENTS.md) first. It defines the current user-facing CLI,
Skill, authentication, observability, and safety contract. This file adds
repository-development guidance for Claude Code; it does not override the live
parser or bundled Skill.

## Runtime Sources Of Truth

Do not infer commands from this document. From the checkout, run:

```bash
PYTHONPATH=src python -m maxc_cli agent manifest --json
PYTHONPATH=src python -m maxc_cli <command> --help
PYTHONPATH=src python -m maxc_cli agent skill --json
```

The public Skill is `alibabacloud-maxcompute-cli`. Its source is
`src/maxc_cli/skills/`; install locations are generated by
`src/maxc_cli/agent_platforms.py`. The preferred public entry is
`aliyun maxc`; `maxc` is the standalone Python entry.

## Architecture

```text
cli.py -> app.py -> backend/*.py -> PyODPS / MaxCompute
              |-> config.py
              |-> models.py       (Envelope v2 and structured actions)
              |-> cache.py        (metadata and semantic SQLite cache)
              |-> store.py        (job follow-up context)
              |-> audit.py
```

`OdpsBackend` is the only production backend. It is composed from the query,
job, metadata, data, auth, and catalog mixins under `src/maxc_cli/backend/`.
New MaxCompute capabilities should normally extend these mixins; introducing a
second production backend requires an explicit architecture decision.

Public SQL execution is SELECT-only and uses a positive allowlist. The hidden
`--force` compatibility surface is not an Agent API. `data upload` is a
separate, explicit Tunnel write command and must keep its dry-run,
`--create-partition`, and overwrite boundaries.

## Machine Contract

Normal `--json` commands return Envelope v2 with:

- `status`: `success`, `pending`, or `failure`;
- typed `error` with recovery information on failure;
- structured `agent_hints.actions` as the authoritative follow-up contract;
- legacy `next_actions` only for executable, confirmation-free, agent-allowed
  actions.

CSV/NDJSON record streams and `job wait --stream` have separate shapes. Before
changing an emitter, update and run the output-shape and manifest contract
tests. Never claim that every command or every streamed record is an Envelope.

`agent context` is strictly local and never proves authentication or network
reachability. `agent doctor --online` owns the live readiness claim. The
`aliyun maxc` wrapper may pass the non-secret
`ALIBABA_CLOUD_MAXC_PROFILE_CONFIGURED=1` hint to local context; this marker is
advisory and must never become a backend credential.

## Configuration And Authentication

- Automatically discovered workspace config may set project behavior but may
  not activate `auth` or an external credential helper.
- Authentication belongs in the user-level config or an explicitly selected
  `--config` file.
- Public interactive login prefers OAuth Authorization Code + PKCE with a
  loopback callback. It is not a device-code flow.
- External credential helpers run as argv with `shell=false`; do not add shell
  pipelines or include helper stderr/commands in user-visible failures.
- Never put credentials into tests, samples, logs, recovery commands, or
  documentation. Use placeholders or environment-based test fixtures.

## Changing Commands

For a new or changed command, keep these surfaces in one change:

1. parser and handler in `src/maxc_cli/cli.py`;
2. application method in `src/maxc_cli/app.py`;
3. backend method when remote work is required;
4. `_manifest_requirements`, `_manifest_effects`, and output-shape contract;
5. a safe, copyable sample in `src/maxc_cli/_samples.py`;
6. relevant bundled Skill workflow/reference;
7. parser, envelope, security, and black-box help tests.

Do not expose an accepted compatibility flag as Agent-allowed when runtime
rejects it. Do not use argparse abbreviation; every parser has
`allow_abbrev=False`.

## Validation

The supported Python floor is 3.9. A normal source validation is:

```bash
ruff check src/ tests/
python -m pytest -q
python -m pytest -q -m e2e tests/test_help_version_e2e.py tests/test_e2e_smoke.py
bash -n scripts/bootstrap.sh
bash -n scripts/bootstrap-ncs.sh
```

Run `tests/test_integration_real.py -m integration` only with an authorized
MaxCompute account. Run `tests/test_pyinstaller_bundle.py` after rebuilding the
bundle. Validate the bundled Skill with the repository's current Skill Creator
validator and test the rendered `aliyun maxc` invocation.

Preserve Python 3.9 compatibility, Windows path/lock fallbacks, owner-only
state permissions, atomic replacement, and symlink/reparse-point rejection.

## Packaging And Release Boundary

`src/maxc_cli/__init__.py` is the only version source; `setup.py` reads it.
Skill resources are explicit `package_data`, and wheel/sdist contents must
match. `maxc.spec` intentionally excludes optional PyODPS ecosystems not used
by MaxC.

Building, committing, publishing to PyPI/OSS, flipping the public latest
pointer, and releasing the Alibaba Cloud CLI wrapper are separate gates. A
source commit does not prove that a public bundle or wrapper is deployed. Do
not publish, flip pointers, or push another repository unless the user has
authorized that exact side effect.
